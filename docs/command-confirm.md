# 두 번 확인: 위험한 명령은 화면이 한 번 더 묻는다

| 항목 | 내용 |
|---|---|
| 상태 | 구현(2026-11-25). 9장은 초안 값(바꿀 수 있음) |
| 대상 | 워커 계약의 명령 정의, 화면 공용 셸(`ui/web/shell.js` `api`) |
| 왜 | 시동·재부팅·SD 포맷처럼 되돌리기 어려운 명령의 확인 창이 패널 코드마다 따로 있었다. 새 패널이 잊으면 그냥 나가고, 자동 화면은 묻지 않았다(`docs/review-2026-11-25.md` 6장 한계 4) |
| 바탕 | design.md 6.6.7.1(명령 정의 `read`·`operate`), `docs/command-path.md` |

## 1. 구조

| 자리 | 하는 일 |
|---|---|
| 계약 | 명령 정의에 `"confirm": "<물을 문구>"`. 워커 정의(`io/self.json`)·조각·역할 정의 어디든. 읽기 명령(`read`)에는 쓰지 않음 |
| 화면 | 셸 `api()`가 `POST /workers/{id}/command`를 보내기 전에 그 워커 계약(`GET /workers/{id}/io`, 워커마다 30 s 기억)에서 명령 정의를 찾아, `confirm`이 있으면 `문구 + (워커 · 명령)`으로 묻는다. 취소하면 보내지 않고 알림도 없음 |
| 패널 | 할 일 없음(모든 패널·자동 화면이 `ctx.api`로 보냄). 패널이 따로 띄우던 확인 창은 계약에 옮기고 지운다 |
| 게이트웨이·바깥 프로그램 | 바뀌지 않음(묻는 것은 화면 일. 바깥 프로그램은 만든 쪽 책임) |

- 본보기: 틀 역할 정의 `example`의 `source.reset`
- 점검: `dev/test_workers.py` — `confirm`은 비지 않은 글, `read`와 같이 쓰지 않음

## 3. 시험

| 무엇 | 어떻게 |
|---|---|
| 점검 | 빈 문구·읽기 명령에 쓰면 실패 |
| 화면 | 브라우저: `source.reset`을 보내면 문구로 묻고, 취소하면 요청이 나가지 않음 |

## 9. 함께 정할 것 (초안)

| # | 항목 | 초안 |
|---|---|---|
| 1 | 칸 이름·값 | `confirm`: 물을 문구(글). 있으면 묻고 없으면 안 물음 |
| 2 | 묻는 창 | 브라우저 확인 창(`window.confirm`), 끝에 `(워커 · 명령)` |
| 3 | 바깥 프로그램 | 강제하지 않음(게이트웨이 확인 번호는 나중에 필요하면) |
