# 워크스페이스 현황 검토 (2026-11-25, 문서 버전 0.86)

공용 개발 워크스페이스(공개 저장소)의 지금 상태를 한곳에 모은 검토용 문서. 프로젝트(DURU) 적용은 빼고 플랫폼만.

## 1. 한 줄 요약

- 계획한 플랫폼 일은 모두 구현·시험·배포. 보드(Jetson)에서 동작 확인
- 필수로 남은 일 없음. 남은 것은 **정할 것(초안 값)**, **알려진 한계**, **선택 개선**

## 2. 구조

```text
 브라우저 ─ HTTP/HTTPS ─▶ nginx ─┬─▶ 화면 파일(ui/web) 직접
                                 ├─▶ /media/ → MediaMTX(영상 보기·신호)
                                 └─▶ 게이트웨이(C++) ─ 신분·권한·모드·명령 기록·설정
                                          │
              ┌───────────────────────────┼───────────────────────┐
              ▼                           ▼                       ▼
      process-manager            매니저 6개(판단)            워커 명령 소켓
   (워커 띄우기·감시·연결)   record·status·mission·          (읽기는 바로,
                             payload·fault·config            나머지는 mission 거침)
                                          │
                                   계약(io.json)·연결 선언
                                          │
                                 장치·처리 워커(libworker)
```

## 6. 알려진 한계 · 정할 것 (2026-11-25 논의 후 1~6 고침, 0.87)

| # | 무엇 | 지금 | 제안 |
|---|---|---|---|
| 1 | 워커가 `busy`·`forbidden`으로 답하면 HTTP 500 | 설계(9.6)상 의도. 게이트웨이 자체 막음은 403 | 403(forbidden)·409(busy)로 바꾸는 편이 화면·외부 UI가 다루기 쉬움 |
| 2 | `/media/`는 로그인과 상관없이 열림 | 8889를 바로 여는 것과 같음 | 로그인을 켜는 장비면 nginx `auth_request`로 막기(nginx-light에 모듈이 있는지 확인 필요) |
| 3 | 화면 스트림 연결 수 | 패널에 따라 브라우저 한도(6)에 가까움 | 게이트웨이에서 여러 스트림을 하나로 묶기(선택 개선) |
| 4 | 두 번 확인 | 없음 | 위험 명령(시동·재부팅 등)에 계약 표시 → 화면이 한 번 더 묻기(선택 개선) |
| 5 | 장치 워커의 이벤트 발행 | 틀 워커만 `take_events`를 발행 | 스트림을 내는 모듈이 늘 발행하도록 libworker가 대신 붙여 주는 길 검토(지금은 모듈 책임) |
| 6 | 화면에서 다시 시작 | 없음("다시 시작하면 적용" 표시만) | 필요하면 따로 설계(화면 스스로를 끊는 일) |
| 7 | 보드 SSH | 인터넷 쪽에서 root 비밀번호 대입 시도(오늘 85번) | 비밀번호 로그인 끄기(sudo 필요, 직접) |

## 7. 초안 값 모음 (각 설계서 9장)

| 문서 | 초안 값 |
|---|---|
| `docs/modes.md` | advisory 칸 `{code, message, condition}` · 이벤트 `command_would_block`·`fault_action_held` · `fault.run_action {id, stage?}` · `PUT /mode` 없앰 · 미리 보기 `WORKSPACE_ACCESS_MODE=operation` |
| `managers/mission/priority.md` | 키 = 보낸 곳(앞부분 `*`) · 같은 값은 온 순서 · 밀어내기는 큐가 찼을 때 가장 낮고 늦은 것 · 잡아 두기 `hold_ms` 기본 0 · 거절 `busy` |
| `managers/mission/conditions.md` | 쓰는 값 = 상태·지표·모드 · 모르면 막음(`allow`로 풀기) · `except` · 거절 `forbidden`(워크스페이스는 advisory) · 읽기·`lease.renew`는 안 봄 |
| `managers/mission/external-link.md` | libworker가 `peers.json` `entry`로 감쌈 · 허락 검사는 mission `via` · 읽기·`lease.renew` 빠른 줄 · mission 없으면 `unavailable` |
| `managers/fault/escalate.md` | `all`·`any` 4단 · 시스템 전체로 판정, 이상 이름 = 규칙 id(잎 하나 규칙은 `<규칙>:<워커>`) · `for_s` · `stages` · 단계마다 한 번 · ack는 단계를 멈추지 않음 |
| `docs/input-check.md` | 스키마 있는 주제만 · 1 s에 한 번 · 막지 않음(셈·이벤트 60 s에 한 번) · 기본 켬 |
| `managers/record/retention.md` | 워커 5 s/60 s · 관리 주제 5 s · 14일·8 GB·빈 곳 4 GB · 새 파일 + 10분마다 |
| `docs/media-proxy.md` | `/media/` · nginx 뒤면 자동 · 로그인과 상관없음 |
| `ui/workspace-screen.md` | 탭 여섯 이름 · 바로 적용 3칸 · 화면에서 다시 시작 없음 · 위 띠 "정상·주의·이상" + "개발/제품" |
| `ui/worker-panels.md` | 운용·상태·도구 · 처음 운용 · 도구는 개발만 · 버튼 감도는 설정 창 · `?tab=` |
| `ui/system-panel.md` | 매니저는 계약으로 찾음 · SSE 2 Hz(system·fault 늘, 나머지 열려 있을 때) · 임대는 5 s마다 · 조작은 이상 확인만 |
